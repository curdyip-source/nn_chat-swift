# История правок — NufNaf Chat (iOS)

Человекочитаемый журнал заметных изменений. Технические детали — в git-коммитах.

## 2026-08-06

### Способ заказа может быть не выбран
- Заказы с сайта приходят без способа заказа — модель заказа теперь читает пустой способ (`orderMethodID: Int?`). В «Параметрах» такой заказ показывает «-», в шапке карточки СРМ способ просто не выводится. При редактировании заказа способ по-прежнему обязателен — то есть менеджер выбирает его сам, как и задумано.
- **Билды до 36 заказ без способа прочитать не могут** (поле было обязательным) — на бэкенде такие заказы включать только после выката этого билда и подъёма `min_supported_ios_build`.

### Оплата заказа
- В карточке заказа в СРМ («Все заказы» и «Отгрузки») строка «Итого» получила надпись-кнопку **«Итого: 15 999₽ (Оплатить)»**. Нажатие открывает привычное модальное подтверждение (`AppConfirmCard`), после подтверждения надпись становится зелёной **«(Оплачено)»** (неоплаченные — нейтральным серым, оплаченные видно по списку); нажатие на неё предлагает отменить оплату. Без «бабла» — в карточке уже есть баблы статуса заказа и статусов товаров.
- В карточке заказа (экран заказа) в «Параметрах» — строка **«Оплата»**: «Не оплачено» либо «Оплачено · дата · кто отметил».
- Под капотом: `PUT /orders/{id}/payment`, поля `order_paid*` в модели заказа (декодер backward-safe — старые карточки из кэша читаются), список обновляется как при смене статуса.

### Суммы — разряды тысяч
- Все денежные суммы в приложении показываются с пробелом между тысячами: **17 308.00** вместо 17308.00. Единый формат — `AppAmount` (`Shared/Formatting`): карточки заказов и позиций в СРМ, экран заказа (цена/сумма/итого), превью заказа в чате, документы (инвентаризация/оприходование), «Прайс». Копирование номенклатуры из заказа осталось без пробелов — чтобы цены вставлялись в таблицы как числа.

## 2026-07-22 (build 33–34)

### Форс-апдейт — гейт минимальной версии (build 34)
- Приложение читает `min_supported_ios_build` из reference-data и сравнивает со своим `CFBundleVersion`. Если билд ниже — **полноэкранный блокер** «Обновите приложение» поверх всего с кнопкой «Открыть TestFlight», дальше не пускает.
- Порог задаётся из веб-«Админки» (только админ). `0` = выключено. Работает начиная с этого билда (34).

### Канал продаж (Розница / Опт / Дроп)
- В композере заказа — выбор канала кнопками **перед складом** (значения из справочника `sales_channels`). При выборе клиента канал **подставляется автоматически**, при «Сохранить клиента» — уходит в контакт.
- Канал добавлен в модели заказа/контакта/reference-data (backward-safe декодер), в create/update-запросы.
- Виден в **«Параметрах»** заказа и в шапках СРМ: «Все заказы» (`Канал · Склад · Метод · Клиент`) и «Отгрузки» (`Заказ № · Канал · Склад · Кол-во · Цена`).

### Ошибка прав — глобальное окно
- Ошибки прав (**403**) показываются модальным окном **«Недостаточно прав»** поверх всего (кнопка «Хорошо») вместо разрозненных красных надписей в блоках. При 403 на создании заказа оптимистичная карточка убирается из чата (нет «зависшего» заказа с красным восклицательным).

### СРМ — Товары
- Сортировка внутри статусной группы по `order_item_id` — **свежий товар вверху** независимо от возраста заказа.
- Количество **«N шт.»** — жирным и тёмным.
- Подпись заказа вынесена **отдельной строкой на всю ширину** (название+статус одной строкой) — цена не обрезается блоком статуса.

### СРМ — Отгрузки
- Кнопка заказа: **«Выполнено» → «Выполнить»**.
- Кнопка товара: **«Собран» → «Упаковать»** (фиолетовая активная) / **«Упаковано»** (серая неактивная — вместо зелёной, чтобы не выглядела нажимаемой).

### Исправления
- При выборе сохранённого клиента подставляется **способ связи** (`contact_contact_method`) — раньше поле не читалось обратно и кнопка WA/TG/… не подсвечивалась.

## 2026-07-04

### Права доступа — гейтинг режимов + реалтайм
- **Свайп-пейджер по правам**: режимы **СРМ** и **Прайс** доступны только если админ их разрешил (разделы пользователя). «Чат» доступен всегда. Недоступные режимы не показываются в свайпе.
- **Реалтайм-смена прав**: по SSE-событию `user_updated` про текущего пользователя приложение перечитывает `/me` и применяет доступ на лету, без перезахода. Если отозвали доступ к текущему режиму — возврат на «Чат».
- **Заказы по складам**: карточки заказов недоступных складов больше не показываются (сервер фильтрует ленту по правам склада). При реалтайм-отзыве склада приложение перезабирает ленту с нуля — карточки исчезают сразу.

### Прайс
- Режим «Прайс» — временно пустой (чёрный) экран: откат встроенного WebView веб-прайса, остаётся только сама свайп-страница под будущую нативную реализацию.

## 2026-07-03

### СДЭК (доставка) — новая интеграция
- В карточке заказа (метод СДЭК) — блок **«СДЭК»**: кнопка «Создать накладную» либо трек-номер + статус, иконка копирования трека, иконка **«Пересоздать»** (сброс накладной + форма заново, с подтверждением-alert).
- **Форма создания накладной** «как в приложении СДЭК»: получатель (ФИО/телефон), **Откуда** — город + ПВЗ отправителя (сдача в ПВЗ; пусто = курьер), **Куда** — город получателя + ПВЗ по адресу или курьер, габариты, выбор тарифа (цена/сроки), доп. услуги (объявленная стоимость, страхование, СМС, наложенный платёж, оплата доставки). Города/ПВЗ ищутся по названию/адресу — без кодов.
- **Статусы** обновляются автоматически (вебхук на сервере + при открытии карточки) — ручной кнопки нет.
- **Префилл** данных клиента: при создании заказа методом СДЭК и в форме накладной подставляются данные из прошлых заказов клиента; город/ПВЗ сохраняют коды (тариф грузится сразу). ПВЗ отправителя — из последнего использованного.

### Композер заказа / клавиатура
- Тап по кнопкам выбора (Склад / Способ связи / Метод) закрывает клавиатуру.
- Тап в поле «Информация» поднимает его под свитчер, чтобы кнопки были видны.
- Клавиатура полей композера приведена к единому светлому виду.

### Сборка / окружение
- Две схемы **Local / Prod** — адрес бэкенда выбирается при сборке (выпадашка схемы в Xcode). **Local** (Debug): build-фаза подставляет `http://<IP-Mac-в-Wi-Fi>:8001/api/v1` (IP определяется автоматически); **Prod** (Release): `https://chat.nufnafchat.su/api/v1`. Archive для TestFlight — всегда Prod.
- Добавлен свой `Info.plist` (API_BASE_URL + ATS `NSAllowsLocalNetworking` — для локального http по LAN).

### Статусы заказа и отгрузки
- Статус позиции **«Собрано»** теперь тоже проходит гейт перевода заказа в «На сборку» (сохраняя свой статус) — в «Отгрузках» позиция сразу отмечена собранной; при сплите остаётся в заказе вместе с «В наличии».

## 2026-07-01

### CRM
- Поиск в CRM: клавиатура закрывается тапом вне поля, свайпом по списку, крестиком (заодно чистит текст) и мгновенно на старте свайпа в режим чата (раньше висела до оседания страницы).
- Фильтр: иконка в шапке подсвечивается зелёным, если задан хоть один не-дефолтный критерий (год, месяцы, виды, методы, склады, статусы, «скрыть выполненные») — чтобы не забыть про оставленный фильтр. Переключение чат/CRM критерием не считается.
- Мультивалютные итоги в карточках «Все заказы» показываются суммой по каждой валюте (`10₽ + 55$`) вместо «N поз.».

### Заказ
- В карточке заказа раздел «Позиции»: у каждой позиции добавлена «Сумма» (цена × кол-во) и общий «Итого» (по валютам через ` + `, справа).
- Кнопка копирования позиций рядом с заголовком «Позиции»: копирует список `Наименование * N шт. * Цена валюта` и итог.

### Композер заказа
- Цена позиции очищается при тапе — сразу вводится новое значение.
- Количество позиции: к кнопкам −/+ добавлен ручной ввод (тап очищает поле, `numberPad`, 1…999); внешний вид контрола не изменился.
- Позиция заказа всегда шлёт снимок (артикул+название) при обновлении — заказ не ломается «Товар не найден», даже если товар удалён/пересобран при федерации каталога.

### Чат
- Непрочитанные комментарии заказа: красная цифра на карточке гаснет сразу после прочтения (раньше висела, пока экран не перерисуется по другой причине).
- Поле ввода снова растёт вверх при многострочном тексте (до 4 строк, как в Telegram); кнопки отправки/скрепки на месте. Регрессия после переноса композера в UIKit-ядро.

### Фильтр
- «Скрыть выполненные» — теперь включён по умолчанию; текст-описание убран.
- Добавлен «Скрыть отмененные» (тоже включён по умолчанию) — прячет заказы в статусе «Отменен».

### Статусы заказа и отгрузки
- Из ручного селекта статуса заказа убраны «Собран» и «Выполнен» — их ставит только флоу отгрузки.
- Перевод в «На сборку» разрешён, только когда все товары «В наличии» (или отменены: «Не будет»/«Отменен») и есть хотя бы один «В наличии»; при переводе «Не будет» → «Отменен» автоматически. Ошибка гейта показывается оверлейным алертом.
- Отменённые позиции не показываются в отгрузке и не мешают собрать/выполнить заказ (собран = все НЕотменённые в «Собрано»); в карточке заказа они остаются, не удаляются.
- **Сплит заказа (частичная отгрузка):** при переводе смешанного заказа в «На сборку» — диалог «Разделить заказ?»: товары «В наличии» уходят на сборку, остальное — в новый заказ-дубль (бэкенд, атомарно). Доступно из карточки заказа, CRM-карточки и превью в чате.

## 2026-06-27

### Realtime / синхронизация (фаза 2)
- Локальный кеш чата на устройстве + дельта-синхронизация по курсору вместо перекачки всей годовой ленты: история показывается мгновенно при запуске, подтягиваются только изменения.
- Живые обновления по SSE (`/messages/stream`): сообщения, статусы заказов/инвентаризаций/приёмок и позиции обновляются в реальном времени.
- SSE-клиент переписан на `URLSessionDataDelegate` (вместо `URLSession.bytes`, который буферил поток на устройстве) — события приходят мгновенно.
- Резервный дельта-поллинг (4с) на случай, если SSE не поднимется на конкретной сети.
- Форс HTTP/2 для SSE; декод событий на главном акторе (фикс Swift 6).

### Производительность
- Мемоизация парсинга дат (`HomeMessageDateParser`) — убрала микро-хитч на середине горизонтального свайпа chat↔CRM (раньше тысячи дат парсились на каждый кадр).

### Уведомления
- Мгновенный refresh чата при приходе пуша в форграунде (раньше ждал до 4с поллинга).

### Анимация открытия/закрытия карточки заказа
- Данные заказа засеваются из кеша — контент (позиции, цены) въезжает вместе с анимацией, а не «вылетает» после загрузки.
- Статусы заказа переведены с `LazyVGrid` на не-ленивую сетку — въезжают вместе со всем контентом, а не «рендерятся на месте».
- Единый путь закрытия для кнопки «Назад» и свайпа (одинаковый сдвиг карточки).
- Клавиатура уходит вниз плавно и синхронно с карточкой (без «улёта вправо» и без рывка-исчезновения).
- Док комментария (текстфилд) уезжает вместе с карточкой при закрытии.
- Убран deprecated `UIScreen.main`.
